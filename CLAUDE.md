# HDML-Components

Lit-based **TypeScript web components** that let an author declare an HDML document in plain
HTML — `<hdml-connection>`, `<hdml-model>`, `<hdml-frame>`, etc. — and a sibling `<hdml-io>`
component that serializes that DOM to FlatBuffers (via `@hdml/*` libraries running in a Web
Worker) and uploads it to an HDIO server. Published to npm as **`@hdml/components`**
(Apache-2.0). Built with Lit 3 + `@web/dev-server` + `@web/test-runner` (Playwright,
chromium/firefox/webkit). Ships **four artifacts** from one source tree: `cjs/`, `esm/`,
`dts/`, and a minified IIFE `bin/index.min.js` (worker inlined as a string).

```bash
npm install
npm run compile_esm        # TS → esm/ (dev iteration)
npm run test               # compile_tst + wtr (Playwright, ~60s timeout)
npm run dev                # tsc --watch + web-dev-server, opens html/index.html
npm run build              # clear + lint + test + compile_all + typedoc → docs/
```

[`ua.ts`](src/hdvl/ua.ts) holds the two constructed sheets, [`properties.ts`](src/hdvl/properties.ts) SPEC §9's 35-property registry. Four elements have bodies ([`view.ts`](src/hdvl/view.ts), the two `plane-*.ts`, [`fallback.ts`](src/hdvl/fallback.ts)); the other seventeen carry tag + family + observed attributes only, and fill in per slice. **All twenty `HdvlElement` subclasses declare `scene(ctx)`** — Contract 1 is complete — and all twenty return `null`, which §2.3 makes a contract-complete answer; eight of them (view, both planes, three scales, both containers) return `null` permanently, because those families emit no group at all. **The frame sits beside them**: [`resolve.ts`](src/hdvl/resolve.ts) is the resolution index — one rect-free depth-first walk per structural change answering view / plane / scale-chain / tip / container / error-unit / effective-`source`, plus `byUid`, and **the only place that knows how an element finds its view** (`HdvlElement.view` is a read of it; there is no `closest()` down here); [`measure.ts`](src/hdvl/measure.ts) is the MEASURE phase and **the only module in `src/hdvl/` that calls `getComputedStyle`**, once per element per frame, resolving `currentcolor` itself and `clip-path` into geometry; [`schedule.ts`](src/hdvl/schedule.ts) is the coalescing rAF loop plus `runFrame` — MEASURE → COMPUTE → PAINT with no interleaving — and the `frameTrace` test seam. The view owns one `ResizeObserver` over itself **and every descendant**, and a capturing `transitionrun` listener for the 1 ms UA sentinel that [`ua.ts`](src/hdvl/ua.ts) declares as longhands. **And the render seam**: [`scene.ts`](src/hdvl/scene.ts) is the renderer-neutral scene contract (types only — `Scene` / `SceneGroup` / `SceneNode`, plus `emptyScene`), [`renderer.ts`](src/hdvl/renderer.ts) the six-method `Renderer` interface **and** the `renderers.create` module seam a test swaps, [`renderer-svg.ts`](src/hdvl/renderer-svg.ts) the one renderer (diffs by `(widget uid, node index)`; never writes to the scene; `textContent` only), and [`measure-text.ts`](src/hdvl/measure-text.ts) the shared memoised offscreen-2D text measurement that the SVG renderer *and* the recording stub both delegate to — it is deliberately **not** private to the renderer. [`kernel/`](src/hdvl/kernel/) holds the **pure** maths and parsing: no DOM, no `getComputedStyle`, no import side effect, and nothing in it may be listed in `sideEffects`. [`clip-shape.ts`](src/hdvl/kernel/clip-shape.ts) resolves a computed `clip-path` into `Subpath[]` against a measured box; [`scale-continuous.ts`](src/hdvl/kernel/scale-continuous.ts) owns §4.5's four continuous transforms, their inverses and `project()` with `clamp`/`reverse` — `sqrt` is resolved to `pow` exponent 0.5 by `continuousSpec()` so exactly one code path exists, and the transforms are **total** (a `log` of zero returns `-Infinity` and does not throw, because V2 diagnoses the *domain* at step 18 and a kernel that threw would leave the validator unable to evaluate the scale it must diagnose); [`ticks-numeric.ts`](src/hdvl/kernel/ticks-numeric.ts) owns §4.8's normative ladders — the `{1, 2, 5} × 10ⁿ` numeric one in its **integer-reciprocal** form (at a negative power the step is a *divisor*, and ticks are generated as `i / divisor` over an integer index range, **never** by repeated addition), plus the log / pow / symlog ladders, which all call it rather than re-deriving one (R12), and continuous `nice`; [`scale-band.ts`](src/hdvl/kernel/scale-band.ts) owns §4.4's band — whose denominator is **`n − 1 + b`, not `n`** (deliberately not d3's `paddingInner`/`paddingOuter`), which returns `{start, width, centre}` whole because **`centre` is what every non-band-filling lookup resolves to** (line vertices, points, rules, ranged endpoints naming a category, and tick/label/grid positions alike), with `start` the **low** edge and `width` never negative so a descending `y` range needs no consumer to normalise it, plus §4.8's ordinal thinning (`count`/`step`/`values`, always from index 0) — `b` is an ordinary parameter with no special case, which is why R19's cluster inner band is this formula at `b = 1` rather than a second entry point; [`project-polar.ts`](src/hdvl/kernel/project-polar.ts) owns §4.6's projection, whose convention is **CSS's, not maths'** — `0deg` at 12 o'clock, angles increasing **clockwise**, the `conic-gradient()` convention — plus §4.3's `min(w, h) / 2` radial ceiling; [`zone.ts`](src/hdvl/kernel/zone.ts) is the **calendar-arithmetic seam** and the only module under `src/` that imports `temporal-polyfill` — four operations (`floorTo` / `ceilTo` / `addUnits` / `fieldsOf`) over **epoch milliseconds**, with no library object crossing it, imported as a ponyfill **value** and never as a global patch and never feature-detected (the native binding is absent on webkit, so a detecting implementation would run different calendar code per engine — asserted against the module's *source*, since no behavioural test can tell a polyfill from a native); and [`ticks-calendar.ts`](src/hdvl/kernel/ticks-calendar.ts) owns §4.8's eighteen-rung calendar ladder, walked **coarsest match first** (the coarsest rung supplying at least `count` boundaries), every boundary computed **in the scale's zone** with `disambiguation: "compatible"` and aligned by snapping the unit's absolute index down to a multiple of the rung — so a spring-forward's collapsed pair is emitted **once, keeping the first** (approved under D1) and a `1d` rung still lands on local midnight across a 23-hour day. It is also the kernel's **one** intra-directory import: *beyond a year* is `ticks-numeric.ts`'s ladder over year numbers, because R12 says a ladder has one implementation; and [`format-skeleton.ts`](src/hdvl/kernel/format-skeleton.ts) owns §4.9's CLDR skeleton → `Intl` option-bag mapping — **the option bag and not a formatter**, because the bag is this repo's own mapping and is asserted exactly on all three engines where a rendered string is ICU data and is asserted on chromium alone (the project's only engine-scoped rule). It carries both token spaces and the disjointness test V14 will classify with (`skeletonKind`, four members: a string in **both** spaces is `"mixed"` rather than `"unknown"`, so step 24 need not re-tokenise it to write its message), §4.9's two caches, and **the shared compact prefix over a value *set***: `formatCompactSet` takes a set and returns one, because SPEC §7 makes axis coherence a property of the label set rather than of the format string, and it is **total** — a skeleton it cannot map falls through to the locale's default formatting — so there is no per-value entry point that could emit `900K, 1.2M, 1.5M` and `hdml-label` and a continuous `hdml-legend`'s ramp share this one implementation. It imports nothing, `temporal-polyfill` least of all: a date skeleton becomes an `Intl.DateTimeFormat` carrying the scale's `timeZone`. Every kernel function normalises `-0` at the source, except `zone.ts` and `ticks-calendar.ts`, where a sweep found no reachable producer — epoch milliseconds are integers and nothing on their paths multiplies by zero. **And the interaction + diagnostics half**: [`events.ts`](src/hdvl/events.ts) is `HdmlPointerEvent` (a real `PointerEvent` subclass carrying `index`/`datum` as **own properties**, because `UIEvent.detail` is a `long` that coerces an object to `0`), the view's one delegated pointer listener with its **mandatory proxy fence** (`if (e instanceof HdmlPointerEvent) return` — without it one native `pointermove` re-enters 44 times on chromium, 448 on firefox and until the stack dies on webkit), and the after-PAINT dispatch queue every outward `hdml-*` event goes through; [`validate.ts`](src/hdvl/validate.ts) is the validator — all 21 `DiagnosticCode`s and 6 `WarningCode`s, the structural pass that runs **inside `reindex()`** (V1, V13, W2), the COMPUTE-side binding seam (named, empty until a `Scale` exists), and MEASURE's W5/W6 sink — and is **the only module in `src/hdvl/` that writes to the console**, which is what makes edge-triggering mechanical: every diagnostic reports once per `(rule, code, channel, message)` identity per error unit, and recovery dispatches nothing; [`supports.ts`](src/hdvl/supports.ts) registers `HDML.supports` additively on `globalThis.HDML` and is imported by `index.ts` for that side effect alone. **And the data-binding half**: [`subscribe.ts`](src/hdvl/subscribe.ts) is Contract 4's **consumer** side and **the only module under `src/hdvl/` that imports [`../hdio/delivery`](src/hdio/delivery.ts)** — `import type`-only, which `check-dist.mjs` check 6 enforces (it also reads `../hdio/config` as a value, for the three discovery-bus event names). It owns subscription identity (keyed by the binding **site** `` `${uid}:${slot}` ``, with a **fresh `id` per instance** because `<hdml-io>` de-dupes by `id`), one `AbortController` per subscription, the ADD/REMOVE/REPLACE reconciler that runs inside `reindex()`, the five adoption duties with the instance fence and the **stamp-not-kind** staleness predicate, the `hdml-io-ready` re-dispatch and the `hdml-io-gone` reset, §3.4's `loading`/paint-suppression quantifiers, and the `hdml-data` producer. An element opts in by implementing the **duck-typed** `Binder` (`bindings()`), exactly as a mark opts into `datumAt` — Contract 1 gained no member. `deliver` **stores and invalidates and never paints, measures or writes a custom state**; §7.4's lifecycle mapping is applied at end of frame by `applyLifecycle`. |

## External contracts

This repo *promises* the following to its consumers; any change here is a cross-repo change.

- **Custom-element registry** — the `.` root entry registers exactly **12** `hdml-*` tag names at module-load time and that number is frozen (R11); the `./hdvl` entry registers **21 more**, the whole display vocabulary, in one commit that never moves again. All tag names are defined in [`@hdml/types`](https://www.npmjs.com/package/@hdml/types) as `HDML_TAG_NAMES` (33 = 12 data + 21 display). Importing `@hdml/components` has side effects; importing `@hdml/components/hdvl` additionally registers SPEC §9's 35 `--hdml-*` custom properties and adopts the fallback rules into `document.adoptedStyleSheets`. See [docs/components.md](docs/components.md).
- **`HDML.supports(tag[, attr])`** — importing `@hdml/components/hdvl` registers a `supports` function on `globalThis.HDML`, **additively** (the namespace object is reused, never replaced, so a page loading two builds or a host app owning `window.HDML` keeps everything else on it). It is **registration-based**: `true` iff this build registered that display tag, and — with a second argument — iff the attribute is in that tag's published `*_ATTRS_LIST`. A page that never imports the `./hdvl` entry gets `false` for all 21. See [docs/decisions.md](docs/decisions.md).
- **`HdmlPointerEvent`** — the display half proxies `pointermove` / `pointerdown` / `pointerup` / `pointercancel` from the widget under the cursor. The proxied event **extends `PointerEvent`** (so `e instanceof PointerEvent` holds and every pointer field survives) and carries `index` and `datum` as **own properties, not `detail`** — `UIEvent.detail` is a `long` and coerces an object to `0` on all three engines. It is `bubbles` + `composed`, dispatched **from the widget** (so series identity is the event target — there is no `series` field), and the native event is **not** stopped: a host app sees both and tells them apart by class. The four named `hdml-*` events (`hdml-data`, `hdml-scale-change`, `hdml-render`, `hdml-error`) stay `CustomEvent`s carrying `detail`, and are all dispatched **after PAINT** from a queue collected during the frame. See [docs/architecture.md](docs/architecture.md).
- **`hdom-changed` DOM event** — every HDQL element dispatches a non-bubbling `CustomEvent<HdqlElement>` on `document` whenever it is connected, disconnected, or has an observed attribute change. `<hdml-io>` is the canonical listener. See [docs/architecture.md](docs/architecture.md).
- **D8 discovery bus** — three `document` events (`bubbles`/`composed`, names configurable via `window.HDML_CONFIG`) are how a data-binding consumer talks to `<hdml-io>`. The seam is an event plus a callback, so **any** consumer can implement it — that is what makes `FakeIo` and the conformance suite possible — and the **first** one is [`src/hdvl/subscribe.ts`](src/hdvl/subscribe.ts), in this package. It dispatches **`hdml-io-request`** carrying a `RequestDetail` `{id, ref, column, raw?, signal?, deliver}` — **`deliver` is required**, and a detail without a function one is rejected outright; `<hdml-io>` announces **`hdml-io-ready`** when it can receive (the symmetric handshake, de-duped by `id`) and **`hdml-io-gone`** at disconnect (the generation space has ended). Delivery is **callback-only**: [`Delivery`](src/hdio/delivery.ts) is the consumer-facing union (`data` / `absent` / `error`, each with a `DeliveryCode` where it can fail), re-exported from [`HdmlIo.ts`](src/hdio/HdmlIo.ts) for external consumers and imported **type-only** from `./delivery` in-repo. Consumers adopt by the **stamp** (`generation >= latest`), not the kind. See [docs/hdio-client.md](docs/hdio-client.md#the-discovery-bus--subscription-registry-step-08-d7d8).
- **HDIO HTTP client** — `<hdml-io host tenant token>` targets the post-006 tenant routes at one base (`host`). There is **no** `sessions` bootstrap: in token mode the `token` attribute is a single-use **handoff code** that `HdioClient` redeems at `POST {host}/{tenant}/api/v1/auth/token` `{token}` for the `{access_token, refresh_token}` pair, held **in memory only** (silently refreshed via `POST …/auth/token/refresh`). It then `POST {host}/{tenant}/api/v1/documents/dynamic` with an `application/octet-stream` body of the `DocumentFilesStruct` FlatBuffers (the whole document, re-sent every change — no dedup) carrying a real `Authorization: Bearer <access>`; the **201** `{ stored[], ddl[] }` response is folded into the ref→key→stored registry. See [docs/hdio-client.md](docs/hdio-client.md).
- **Four entry points** — `.` (the compatibility root: 11 HDQL elements + `<hdml-io>`, exactly what it always registered), `./hdio`, `./hdql` and `./hdvl`, declared in an `exports` map. The three sub-entries are purely additive; `./hdvl` registers the 21 display tags. `exports` is a resolution **fence**, so deep paths like `@hdml/components/esm/hdql/HdmlFrame.js` no longer resolve — that break is intended. See [docs/integration.md](docs/integration.md#entry-points).
- **npm package shape** — `main: cjs/index.js`, `module: esm/index.js`, `types: dts/index.d.ts`, `customElements: custom-elements.json` (CEM, generated by `npm run manifest`), plus the `exports` map and a `sideEffects` array covering both module formats of all four entries; plus an unreferenced IIFE bundle at `bin/index.min.js`, built from `src/bundle.ts` and carrying all three layers. See [docs/integration.md](docs/integration.md).

## Conventions

- **No source comments unless they explain *why*.** TypeDoc `@tagname` / `@attribute` /
  `@event` JSDoc on the class is the public-facing reference — keep it accurate; CEM analysis
  reads it.
- **Attribute property keys are `*_ATTRS_LIST` enums**, not literals — e.g.
  `[CONN_ATTRS_LIST.NAME]: null | string = null` (see [src/hdql/HdmlConnection.ts:159](src/hdql/HdmlConnection.ts#L159)). The enum lives in `@hdml/types`; do not hardcode attribute strings here.
- **Display tag names and attribute keys come from [`src/hdvl/vocabulary.ts`](src/hdvl/vocabulary.ts)** — never a direct `@hdml/types` import in a display element file, and never a literal. That module is the only importer of the display vocabulary, so the 21 tags and 20 attribute enums are auditable in one place. (`src/hdql/` keeps importing its eight data enums directly, as it always has; and `@customElement("hdml-io")` stays a literal, because `HDML_TAG_NAMES` has no `IO` member — `hdml-io` is neither a data nor a display tag.) See [docs/decisions.md](docs/decisions.md).
- **All HDQL elements extend [`HdqlElement`](src/hdql/HdqlElement.ts#L8)**. Subclasses *do not* override the lifecycle hooks — the base hooks `connected`/`disconnected`/`attributeChanged` already dispatch `hdom-changed`. Subclasses only declare `@property` fields.
- **Worker code path:** `src/hdio/HdmlIo.worker.ts` exports `const _script = "_script"` as a build-time sentinel. The custom esbuild plugin in [.esbuildrc.mjs:8-45](.esbuildrc.mjs#L8-L45) bundles the worker and rewrites this constant to the bundled source string in the IIFE build only. In `esm/`/`cjs/` builds the sentinel survives, and `HdmlIo` falls back to running the message handler on the main thread (`globalThis.self`). See [docs/decisions.md](docs/decisions.md#why-_script).
- **Lint/format rule that bites:** `max-len: 70`, `printWidth: 70` (ESLint + Prettier). Wrap aggressively.
- **TypeDoc output is isolated under `docs/api/`.** `npm run docs` writes generated HTML to `./docs/api` and `npm run clear` removes only `docs/api` — so the hand-written agent docs (`docs/*.md`) survive a `clear`/`build`. The [.gitignore](.gitignore) ignores `docs/*` and re-includes `!docs/*.md`, so `docs/api/` stays untracked while the `.md` are committed. (Previously `clear` did `rm -rf docs`, deleting the tracked `.md` from the working tree; that TODO is now resolved.)
- **Tests use TDD-style globals.** `.testrc.js` sets `ui: "tdd"` — write `suite` / `test`, not `describe` / `it`. See an example at [src/hdql/HdmlConnection.test.ts:11](src/hdql/HdmlConnection.test.ts#L11).
- **Two export conditions.** `MODE=prod` selects the `prod` package export condition (both dev server and test runner); the default uses `development`. `TODO(confirm: which @hdml/* package actually publishes both conditions and what the dev one swaps in.)`
- **License header.** Every TS source carries the four-line `@author / @copyright / @license Apache-2.0` JSDoc preamble. Preserve it.
